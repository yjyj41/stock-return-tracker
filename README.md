# Stock Return Tracker

삼성증권과 Trading 212 ISA/Invest·CFD 거래내역을 읽어 매매 손익을 확인하고, 대출과 지출을 각각의 탭에서 관리하는 사이트.

브라우저에서 동작하는 클라이언트 전용 앱입니다. 데이터는 브라우저 localStorage에 저장됩니다.

## 파일
- `index.html` — 메인 페이지
- `support.js` — 지원 스크립트
- `importers.js` — 파일 자동 인식과 손익 계산
- `portfolio.js` — 계산 기준 선택, 환율 조회, 중복 없는 원화 합산
- `loans.js` — 대출 잔액 기록, 일별 이자 추정, 납부일·상환 계획
- `spending.html`, `spending.js`, `spending-core.js` — 지출 CSV 분석·예산·구독·저축 목표와 저장 형식 호환
- `tests/spending.test.cjs` — 지출 CSV 부호·중복·백업 호환·입력 검증
- `tests/importers.test.cjs` — 파싱·손익 계산 회귀 테스트
- `tests/portfolio.test.cjs` — 환율·계좌 합산·보고값 비교 검증

## 사용법과 계산 기준

상단에서 **국내 · 삼성증권**, **해외 · Trading 212**, **전체 합산**을 선택합니다. 국내와 해외의 거래 목록·통계·차트·캘린더는 분리됩니다. 국내에 거래내역이 있으면 종목별 매매 화면을 우선 열며, 일별 손익표로 전환할 수 있습니다. 해외에서는 ISA/Invest와 CFD, 통화를 각각 선택합니다. 전체 합산은 별도 화면에만 표시하며 항상 비용 포함 기준입니다.

**삼성증권 전체 순수익은 순손익 열이 있는 손익표가 필요합니다.** 상단 전체 순수익·통계·누적 그래프는 항상 손익표 기준이며, 종목별 거래내역을 선택해도 바뀌지 않습니다. 거래내역만 있으면 상단은 손익표를 안내하고 아래 종목별 기능은 정상 제공됩니다. 기존·직접 입력 기록도 보관되지만 순수익 합산에는 포함하지 않습니다.

종목별 목록·필터·손익 합계·매수/매도 가격과 날짜·캘린더를 제공합니다. 거래를 펼치면 국내 가격 차트, 매수/매도 기록, 반영된 비용, 계속 보유했을 때의 평가손익을 확인합니다. 평가손익은 매도한 수량을 최근 종가까지 보유했다고 가정하며 기준일을 표시합니다. 확인된 매수비용은 포함하고 가상 매도비용·신용이자는 제외합니다. 가격이 매도일 이전이거나 조회에 실패하면 값을 만들지 않습니다. 해외 시세 차트는 제공하지 않습니다.

파일 불러오기에서 CSV/XLSX/XLS를 선택합니다. 같은 종류의 파일을 다시 불러오면 그 종류의 기록을 교체합니다. 이전의 직접 입력 기록과 다른 종류의 파일은 보존됩니다. 여러 기간을 계산하려면 전체 기간을 포함한 파일을 불러오세요. 이전 버전에서 가져온 기록은 원본 파일을 다시 불러와 수정된 계산을 적용할 수 있습니다. 비용을 확인할 수 없는 직접 입력·붙여넣기 기능은 순수익 화면에서 제공하지 않습니다.

- **삼성증권 거래내역:** 국내주식만 처리합니다. 날짜를 오름차순으로 정렬하고 날짜별 매수를 먼저 합산해 이동평균 매입원가를 계산합니다. 같은 결제일·종목·매수/매도별 현금금액을 NXT와 함께 묶어 체결금액과의 차이로 수수료·세금을 구합니다. 매수비용은 이동평균 원가에 포함하고 일부 매도분에 비례 반영합니다. 융자·현금금액 누락·불명확한 수수료 표기·융자와 혼합된 원가는 비용 전 추정으로 표시합니다. 대출 원금 상환을 비용으로 처리하지 않습니다. `수수료(수량)` 표기는 괄호 안을 수량으로 읽지만 추가 비용이 불명확해 순손익을 확정하지 않습니다. 별도 신용이자·배당은 제외합니다. 결제일·원가 방식이 공식 손익표와 다르므로 종목별 합계를 공식 전체 순수익에 억지로 맞추지 않습니다. 보유 중인 주식은 실현손익에서 제외합니다. 매수 상세는 원가 풀의 보유 구간 기록이며 매도에 대응하는 개별 매수 수량을 지정하지 않습니다.
- **삼성증권 손익표:** 매매일자·매수금액·매도금액·순손익 열을 인식합니다. 순손익 값을 그대로 사용해 수수료·세금 차감 후 일별 합계와 상단 전체 순수익을 표시합니다. 종목별 거래내역과 중복 합산하지 않습니다.
- **Trading 212 ISA/Invest CSV:** `Time`과 `Time (UTC)`를 인식하고 소수점 수량과 통화별 집계를 지원합니다. 전체 매입 내역이 있으면 같은 계좌 통화의 매수·매도 `Total`과 이동평균 원가로 비용 포함 손익을 계산합니다. Total에는 거래 비용이 이미 들어 있으므로 FX 수수료 등을 다시 빼지 않습니다. `Result`는 비용 포함 손익과 다를 수 있어 거래별 참고값으로 보존합니다. 원가가 없는 경우 Result를 그대로 표시하되, 정확한 비용 차감 후 순손익으로 표시하지 않습니다. 배당·현금이자는 매매손익에서 분리합니다.
- **Trading 212 CFD CSV:** `Record Type`을 인식해 `Closed position` 행의 `Total result (account currency)`만 합산합니다. 부분 청산과 롱·숏을 지원합니다. Order 행을 다시 거래로 세거나 별도 Overnight interest·Dividend adjustment 이벤트를 중복 합산하지 않습니다. Total result에 들어 있는 FX fee·이자·배당 조정을 다시 차감하지 않습니다. 명목 거래금액은 증거금이 아니므로 투자금 대비 수익률을 계산하지 않습니다. 가격은 종목 통화, 손익은 계좌 통화로 표시합니다. 미청산 평가손익·미청산 포지션 관련 이자와 배당은 청산 합계에서 제외될 수 있습니다.

ISA/Invest와 CFD는 같은 통화라도 별도 화면에 표시합니다. 매입원가가 없고 공식 Result도 없으면 잘못된 수익 대신 오류를 표시합니다. 주식분할 등의 기업행동 이후에는 Result 없이 원가를 추정하지 않습니다. CFD에 필수 열 또는 Total result가 없으면 오류로 안내합니다. 날짜는 원본 CSV의 UTC 날짜를 유지합니다.

## 한국·영국 합산과 손익 기준 비교

전체 합산 화면에는 삼성증권 손익표, Trading 212 ISA/Invest, CFD를 포함합니다. 삼성 거래내역의 추정치는 항상 제외합니다. 거래내역이 있고 손익표가 없으면 전체 합산액을 숨기고 순손익표가 필요하다고 표시합니다. 기존·직접 입력 기록도 합산에서 제외합니다. 계좌별 실제 매도·청산 기록 기간을 함께 보여 줍니다.

- **비용 포함:** 삼성 순손익 / ISA·Invest 매수·매도 Total / CFD 청산 Total result를 사용합니다.
- **앱 표시 비교:** 해외 화면의 접힌 비교 메뉴에서 ISA·Invest CSV Result / CFD Result after FX fee를 선택할 수 있습니다. CFD 이자·배당 조정 등은 제외됩니다. 현재 앱의 조회기간이나 미실현손익 포함 범위가 다르면 앱 숫자와 완전히 일치하지 않을 수 있습니다. 원본 비용 포함 값을 수정하지 않고 해외 계좌 표시 기준만 전환합니다. 국내와 전체 합산은 항상 비용 포함 기준입니다. 새로고침하거나 계좌를 바꾸면 비용 포함 기준으로 돌아갑니다. 보고값이 누락된 거래는 비용 포함 값을 쓰고 안내합니다.

[Frankfurter 일별 환율 API](https://frankfurter.dev/)에서 외화 1단위의 KRW 기준 환율을 조회합니다. 통화쌍만 보내며 거래 파일·금액·계좌 정보를 전송하지 않습니다. 적용 환율·기준일·출처를 표시하고 브라우저에 캐시합니다. API 실패 시 저장된 환율의 기준일을 안내하며, 환율이 없는 통화가 있으면 전체 합산액을 숨겨 부분 합계를 총손익처럼 보여 주지 않습니다. 양수인 수동 환율도 입력할 수 있습니다.

원화 합산은 전체 실현손익을 적용 환율로 환산한 참고 값입니다. 거래일별 환율, 실제 환전 비용, 미실현손익을 포함한 계좌 자산 증감이나 세금 신고용 환산 손익은 계산하지 않습니다.

Trading 212 공식 자료: [거래 데이터 CSV와 문서](https://helpcentre.trading212.com/hc/en-us/articles/11700508002845-What-documents-can-I-get-from-Trading-212), [CFD CSV 내보내기와 항목](https://helpcentre.trading212.com/hc/en-us/articles/36243765206301-How-to-export-the-trading-data-from-my-CFD-account), [CFD 손익 구성](https://helpcentre.trading212.com/hc/en-us/articles/31931618377629-What-does-the-CFD-Result-show).

## 대출 관리

별도 **대출 관리** 탭에서 원화 신용대출·마이너스통장을 등록합니다. 처음 등록할 때 은행·대출 이름·확인 날짜·대출 잔액·연 금리·매월 납부일·만기일·상환 방식을 입력합니다. 마이너스통장은 한도와 실제 사용 잔액을 구분하며 잔액은 양수입니다. 납부일·만기는 비워 둘 수 있고 상환 방식은 ‘미확인’으로 저장할 수 있습니다. 모르는 값을 만들어 납부 일정을 표시하지 않으며 모든 상환 조건을 확인한 후 예상 상환표를 제공합니다. 추가 확인할 정보는 대출 설정 메모에 보존합니다.

카카오페이/은행에서 확인한 값을 **잔액·금리 갱신**으로 날짜별 저장할 수 있습니다. 확인 잔액으로 현재 원금을 갱신하며 기존 기록을 유지합니다. 금리를 비워 두면 기존 금리가 유지되고 0%도 가능합니다. 잔액 차이에서 상환액이나 실제 이자를 추정하지 않습니다. 마지막 확인 날짜를 표시합니다. 카카오페이 자동 동기화는 제공하지 않습니다.

원금 상환·추가 사용·실제 이자·금리 변경을 개별 기록할 수도 있습니다. 상환 원금과 함께 납부한 이자는 분리하며 이자만 대출 비용으로 셉니다. 현금 납부 이자는 잔액을 바꾸지 않고, 잔액에 편입된 이자는 원금과 비용에 각각 한 번 반영됩니다. 기준일 전에 현금으로 납부한 실제 이자는 등록할 수 있지만 과거 원금을 만들어 계산하지 않습니다. 기준 잔액에 이미 포함된 입출금은 다시 입력하지 마세요. 같은 날짜의 기록은 저장한 순서대로 처리합니다.

예상 이자는 기록된 날짜의 마감 잔액 × 연 금리 ÷ 365일(윤년 366일 또는 항상 365일 선택)로 계산하며 조회기간 양 끝 날짜를 포함합니다. 잔액 확인일 사이 실제 입출금, 은행의 일중 최대 잔액 규정, 절사·약정 월납입액·휴일 조정·연체이자는 알 수 없어 실제 은행 청구액과 다를 수 있습니다. 현재 값으로 30일 예상 이자를 표시하고 미래 금리·사용액 변화는 가정하지 않습니다. 실제 비용에는 별도로 기록한 은행 이자만 사용합니다.

다음 납부일, 만기일 및 30일 이내 만기를 표시합니다. 31일은 해당 월 말일로 조정하고 당일 납부 이자가 기록됐으면 다음 달로 이동합니다. 만기 경과 시 실제 상환 여부 확인을 안내합니다. 화면에 표시하는 일정이며 푸시/문자 알림은 아닙니다. 만기 일시상환·원금 균등·원리금 균등별 예상 월별 상환표를 제공합니다. 남은 원금·현재 금리·실제 날짜 간격으로 다시 계산한 참고 계획이고 은행 약정 월납입액이 아닙니다. 이전 미납 이자를 자동 추정하거나 예정일을 실제 거래로 기록하지 않습니다.

**전체 합산**에는 별도로 ‘기록한 대출 이자 차감 후 손익’을 표시합니다. 대출 탭의 조회기간과 같은 기간의 공식 삼성 순손익·Trading 212 비용 포함 손익에서 기록한 현금 납부 및 잔액 편입 이자만 차감합니다. 대출 원금 상환과 예상 이자는 차감하지 않습니다. 대출 기록 누락 및 불러온 거래 파일의 기간을 확인해야 합니다. 주식 파일이 없거나 삼성 순손익표·필요 환율이 없으면 결과를 만들지 않습니다. 기본 주식 순손익 합산은 그대로 유지합니다.

대출 자료는 브라우저의 별도 localStorage 키에 저장합니다. 동일 기기·브라우저에서 유지되며 자동 클라우드 동기화는 없습니다. JSON 백업 저장/불러오기를 지원하고 다른 대출은 보존하면서 같은 ID만 교체합니다. 브라우저 데이터 삭제/기기 변경에 대비해 백업을 저장하세요. 변경은 새로고침 전 한 번 되돌릴 수 있습니다. 실제 대출 자료는 서버나 저장소로 전송하지 않습니다.

### 다가오는 납부 일정과 자동 납부 가정

대출 탭 상단에서 30일 이내 납부일을 날짜 순서대로 표시합니다. 오늘·3일 이내 일정은 색으로 강조하며, 오늘/7일/30일 준비할 금액과 예상 원금·이자를 구분합니다. 금액을 계산할 수 없는 일정이 포함되면 전체 금액처럼 부분 합계를 표시하지 않고 ‘금액 확인 필요’와 계산 가능한 금액을 함께 안내합니다. 확인 잔액 기준일 당일의 청구액은 현재 잔액에 납부가 반영됐는지 알 수 없어 금액 확인을 요청합니다. 납부일 누락 대출은 별도로 안내합니다. 납부 일정은 은행 자동이체 실행이나 알림 발송을 의미하지 않습니다.

‘매월 정상 납부 가정’은 기본 켜짐이고 브라우저별로 설정을 저장합니다. 마지막 잔액 확인 기준일 다음날부터 시작해 오늘보다 이전인 예정일의 원금을 갚았다고 가정합니다. 오늘 납부는 아직 준비할 항목으로 남겨 두고 다음날부터 예상 잔액에 반영합니다. 확인 기준일 이전 원금 상환은 만들어내지 않습니다. 마이너스통장은 사용액을 유지하면서 이자를 현금 납부하고 만기에 원금을 상환한다고 가정합니다. 가정상 상환이 끝나도 원본의 실제 미상환 잔액 기록은 보존합니다.

첫 청구액이 며칠분 이자로 과소 계산되지 않도록 한 납부기간의 이자를 추정합니다. 기준일 전 미확인 기간에는 확인 잔액·금리가 같았다고 가정한 참고값을 보태며 실제 이자로 기록하지 않습니다. 은행 계약의 월납입액, 잔액 변동·절사·연체·휴일 조정에 따라 다를 수 있습니다. 이후 실제 원금/금리 변동은 가정 모델에 반영하며 실제 상환이 있는 납부 주기는 가정 원금을 중복 차감하지 않습니다. 새 잔액 확인 기록은 그 날짜에서 가정 계획을 다시 시작합니다. 조건이 없거나 기록과 계산이 맞지 않으면 잔액을 억지로 감소시키지 않고 확인을 요청합니다.

사이트를 열면 현재 한국 날짜로 다시 계산하며, 열린 상태에서는 날짜가 바뀌었을 때 갱신합니다. 원본 거래·실제 이자 비용은 변경하지 않습니다. 전체 합산의 실제 이자 차감 손익에는 실제로 입력한 은행 이자만 반영하고 가정 이자는 차감하지 않습니다. 자동 가정을 끄면 입력 기록 기준 잔액으로 돌아갑니다.

### 소비·이체·고정지출 구분

생활비, 고정지출, 수입, 계좌이체, 환급, 확인 필요를 구분합니다. 소비·예산·차트는 생활비와 고정지출 출금만 포함합니다. 환급은 별도 표시하고 수입−소비+환급에는 반영합니다. 전체 입출금의 차이인 계좌 순유입과 소득은 별개입니다. 분류가 불명확한 송금은 확인 필요로 남기며 해당 금액을 수입·소비에 포함하지 않았음을 표시합니다. 0원 거래는 합계와 확인 건수에서 제외합니다.

거래별 분류를 바꾸거나 같은 이름·같은 입출금 방향에 규칙을 적용할 수 있습니다. 개별 지정, 상대방 규칙, 등록한 고정지출 순으로 우선하며 이름은 공백·대소문자만 정리한 정확한 일치를 사용합니다. 급여 이름과 함께 메모의 Salary/Payroll/Wages를 인식하고 카드 반환 및 Reimbursement는 환급으로 분류합니다. 사용자가 켜는 ‘급여·환급 외 입금은 본인 계좌 이체’ 설정은 명시적 급여·환급 판정 뒤에 적용합니다. 개인 상대방·급여 이름은 공개 코드에 넣지 않습니다. 마지막 분류·고정지출 변경을 한 번 되돌릴 수 있으며 원본 거래·예산·목표는 보존합니다.

고정지출에는 이름, 거래 상대방, 월 예상액(GBP), 납부일, 시작·종료 월을 등록합니다. 같은 상대방의 적용 기간이 겹치면 거절하며 금액이 바뀌면 기존 종료 월과 새 시작 월을 지정할 수 있습니다. 31일은 해당 월 말일로 조정합니다. 실제 출금은 CSV의 출금 월에 합산합니다. 전월분을 다음 달 초에 냈다는 사실까지 추정하지 않으므로 청구 월과 출금 월이 다를 때 원본 기록을 확인하세요. 납부일을 모르는 고정지출도 실제 출금액·날짜를 표시하며 날짜를 만들어내지 않습니다. 예정액과 실제 출금의 차이는 미납액이 아닙니다. 등록 후보는 주거비 메모 또는 월별 반복 패턴을 참고하지만 확인·등록 전에는 고정지출로 확정하지 않습니다.

거래 분류 필터, 검색 결과 입출금 합계, 100건 단위 페이지를 제공합니다. JSON 백업에는 `management`의 분류·고정지출 설정이 포함되고 기존 백업도 읽습니다. `suiknote-spending-settings` 형식의 개인 설정 파일을 가져오면 거래 원본을 교체하지 않고 분류 규칙을 합칩니다. 새 설정은 수익노트에서 관리하세요. 이전 spending-tracker 코드에서 데이터를 다시 저장하면 추가 설정이 보존되지 않을 수 있습니다.

기존 사이트와 같은 `spend_tracker_v1` 저장 형식과 JSON 백업을 사용합니다. 두 GitHub Pages 사이트는 동일한 출처(`https://yjyj41.github.io`)이므로 같은 브라우저 프로필에서는 거래·예산·저축 목표가 자동으로 이어집니다. 두 사이트에서 저장한 변경과 전체 삭제도 같은 지출 데이터에 적용됩니다. 다른 브라우저·기기는 자동 동기화되지 않으며 기존 사이트에서 백업(JSON)을 내려받아 새 지출 탭의 복원으로 가져와야 합니다. 복원은 지출 자료 전체를 교체하고 주식·대출 저장 기록에는 영향을 주지 않습니다. 잘못된 CSV/백업은 오류를 표시하며 기존 기록을 보존합니다.

파일과 거래 기록은 브라우저 안에서만 처리합니다. 지출은 GBP 계좌 금액을 원본으로 유지하고, 파운드와 원화 환산액을 함께 표시합니다. 표시 순서는 파운드 우선·원화 우선으로 선택하며 원본 금액은 바뀌지 않습니다. GBP 이외 계좌 통화가 명시된 CSV는 거절합니다. 예산·저축 목표 입력은 GBP 기준입니다. 전체 합산과 같은 `suiknote_v1_fx`의 GBP/KRW 환율을 공유하며 최신 일별 Frankfurter 환율 조회·직접 입력과 기준일 표시를 지원합니다. 저장한 수동 환율은 자동 조회로 덮어쓰지 않으며, 조회 중 다른 화면에서 적용한 새 환율도 보존합니다. 환율이 없으면 파운드만 확정 표시하고 원화는 확인을 요청합니다. 적용 환율로 전체 금액을 환산하는 참고 값이며 거래일별 환율·실제 환전 수수료는 반영하지 않습니다. 기존 사이트의 통화 기호 설정은 원본 금액의 통화 정보가 아니므로 재환산하지 않습니다. 지출 JSON 백업에는 기존 거래·예산·목표 형식을 유지하며 환율은 별도 브라우저 설정입니다. 지출 수입·지출은 주식 순손익이나 대출 이자 비용 합산에 자동 반영하지 않습니다. 차트 라이브러리 로딩 실패 시에도 거래·예산·목표·백업은 사용할 수 있습니다.
